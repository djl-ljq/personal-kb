# 个人工作知识库

一个人的方法、模板与踩坑记录。人和 AI 都能读，换到哪家公司都能带走。

## 这是什么

不是博客，不是笔记软件，是一个**纯 Markdown + Git** 的知识库：
人用编辑器或 GitHub 网页读，AI 用 clone 或一个链接读，不绑定任何厂商、不依赖任何数据库。

## 目录

| 目录/文件 | 内容 |
|---|---|
| `AGENTS.md` | **AI 读这个**。入口约定：怎么读、怎么协作、四条禁令 |
| `index/TOPICS.md` | 主题索引，一行一个主题，人和 AI 都从这里找 |
| `00_体系使用指南与AI协作流程.md` | 项目七阶段、四种协作模式、信息状态定义、报告生成规则 |
| `01_通用分析与设计方法论.md` | 怎么分析、怎么设计、怎么自检 |
| `02_标准方案与报告模板库.md` | 业务方案 / 建设方案 / 实施方案 / 验收报告 的章节模板 |
| `03_专业知识与行业实践手册.md` | 术语、架构、行业做法 |
| `templates/` | 规格（Spec）、决策记录（ADR）、任务清单 的可复制模板 |
| `digests/` | 每日情报简报归档 |
| `journal/` | 项目复盘（脱敏后） |

## 三个使用场景

**1. 让 AI 按我的方法来干活**
新会话第一句贴仓库地址 + 一句：`先读 AGENTS.md，按里面的约定跟我协作`。
AI 会先读入口，再按 `index/TOPICS.md` 去取需要的章节，不会一口气吞全部。

**2. 自己查**
直接用编辑器全文搜索，或按 `index/TOPICS.md` 定位到章节。不用记目录结构。

**3. 换工作带走**
`git clone` 到新机器就行。私有仓库的话，先把 remote 换到你个人账号下。

## 约定

- 一份文档只回答一个问题。要回答两个，就拆成两份。
- 长期有效的方法进 `00`–`03`；一次性项目产物进 `journal/`；两者都脱敏。
- 每条结论能指出来源。指不出来的，标「待确认」并写验证办法。

## 不要放进来

客户名称、合同金额、内网地址、测试账号、任何 `.env` 或密钥。这套东西可能被公开或分享，默认按「会被外人看到」的标准写。
