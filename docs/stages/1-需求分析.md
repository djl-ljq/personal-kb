# 1｜需求分析

> 把现状摸清，找出真问题——通常不是对方说的那个方案。

## 产出物

- 现状分析、问题与证据、假设清单、干系人清单

## 检查清单

- [ ] 每个问题都有证据（截图/数据/原话），不是推测
- [ ] 区分「他要的功能」和「他要的结果」
- [ ] 记录一线的人工补救动作（流程图上看不见的那些）
- [ ] 列出至少三个干系人及其立场

## 常见坑

- 直接抄客户给的功能清单当需求
- 把行业惯例写成这家公司的现行制度
- 只访谈一个角色（通常是配合度最高的那个）

- 上游：0 立项
- 下游：2 业务架构
